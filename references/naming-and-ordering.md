# 命名与排序规则

这些规则是票据输出顺序和文件名的业务真值。实现采用 `input -> output` 非破坏式复制或提取，不原地改名，不删除 ZIP。

## 类别顺序

按以下固定顺序排序，同一类别内按 `business_date` 升序，再按原文件名稳定排序：

1. 大型交通：机票、高铁、动车、火车票。
2. 酒店：住宿、酒店、民宿住宿发票。
3. 市内交通：滴滴、出租车、网约车、机场大巴、地铁、高速、共享单车等。
4. 其他：保险、餐费，以及无法归入前三类但关键字段可靠的发票。

大型交通优先使用实际乘车或乘机日期；滴滴使用行程日期；酒店可使用入住日期；其他票据通常使用开票日期。排序日期只写入内部 `business_date`，不能自动替代 Excel 的开票日期。

## 文件名

普通发票：

```text
序号、用途-发票号码-价格.ext
```

金额必须来自票面明确的 `total_amount`，去除无意义末尾零并追加“元”。保留普通 PDF 扩展名；ZIP 内目标票据输出为 PDF。

示例：

```text
1、高铁-26317000002270260301-645元.pdf
10、滴滴发票A-26457000000166347261-55.9元.pdf
```

滴滴行程报销单与对应发票共享序号：

```text
10、滴滴出行行程报销单A.pdf
```

行程单的 Excel 行仅使用行程单自身字段，不复制发票号码或税务字段。

## 序号

仅对关键命名字段可可靠识别且实际输出的发票分配连续序号。一个滴滴发票与其行程单共享一个序号；ZIP 中每张有效 PDF 发票占一个序号；OFD 和辅助文件不占号。

## 输出冲突

同名目标不存在时创建；同名且 SHA256 相同则安全跳过；同名但内容不同则在任何写入前以 `collision` 中止。任何未被当前计划声明的 output 文件也视为冲突。
