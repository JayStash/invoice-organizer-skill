# 字段提取规则

统一优先级是：明确识别 > 留空 > 绝不猜测。每一行只描述该行文件自身明确包含的信息。缺失值写入 Excel 时必须是真正空白，不能使用 `0`、`None`、`null`、`N/A`、`未知`、短横线或斜杠代替。票面明确显示数字 0 时才写 0。

## 发票号码

- 仅从票面明确标注的“发票号码”提取。
- 订单号、电子客票号、流水号、申请单号、ZIP 名称和文件名数字都不能替代。
- ZIP 内 PDF 必须解析 PDF 自身；不能从 ZIP 名称获取。
- 未明确找到时留空。

## 费用类型

- 机票、航空运输、铁路电子客票、高铁、动车、火车、铁路及明确的长途车船票据：`飞机车船费`。
- 酒店、住宿、民宿住宿票据：`住宿费`。
- 滴滴、网约车、出租车和明确的市内打车票据：`打车费`。
- 餐费、保险及明确不属于前三类的费用：`其他费用`。
- 依据不足时留空。不得使用这四个值之外的文本。

## 票据类型

- 只提取票面明确标题，例如 `电子发票（普通发票）`、`电子发票（增值税专用发票）`、`铁路电子客票`、`滴滴出行-行程单`。
- 程序内部类型（如 `invoice_pdf`、`archive_pdf`、`didi_report`）不能写入 Excel。
- 无法确认标题时留空。

## 不含税金额

- 仅提取明确标注“不含税金额”“合计金额（不含税）”的值，或标准增值税发票中同时明确显示的“合计 金额/税额”金额列。
- 只有价税合计和税率时，不反算不含税金额。
- 不使用文件名金额、单行项目价或其他票据的数据。

## 税率

- 只有票面明确显示税率时提取，并保留如 `6%` 的表达。
- 检测到多个不同税率且没有唯一整体税率时留空，并可备注“存在多个税率”。
- 不根据费用类型、税额或行业惯例推算。

## 税额

- 提取票面明确的“合计税额”“税额合计”，或标准发票“合计 金额/税额”中的税额列。
- 存在多条明细税额但没有明确总税额时留空；不得自行求和。
- 不从不含税金额、总金额或税率计算。

## 燃油附加费

- 仅从“燃油附加费”或票面明确等价字段提取。
- 机票未显示该字段时留空，不按航线、票价或政策推算。

## 民航发展基金

- 仅从“民航发展基金”或票面明确等价字段提取。
- 未显示时留空，不按机票类型、日期或政策推算。

## 票面总金额

- 提取票面明确的“价税合计（小写）”“价税合计”“合计金额”“总金额”“实付金额”或语义明确的票价。
- 铁路电子客票可提取明确标注的票价。
- 滴滴行程单可提取行程单自身明确显示的合计。
- 禁止用文件名金额替代，禁止用不含税金额加税额计算。

## 开票日期

- 仅从票面明确标注的“开票日期”提取。
- `invoice_date` 与 `business_date` 是两个独立字段。
- 出行、乘车、乘机、入住、消费日期可以用于业务排序，但不能自动写入“开票日期”。

## 备注

- 默认留空。
- 仅记录对用户核对有帮助且真实发生的内容，如“存在多个税率”“ZIP 内提取”“配套行程单”。
- 不写内部路径、SHA256、状态、调试信息或异常堆栈。

## DiDi

发票与行程单按现有 A/B/C 规则配对并共享序号，但各自独立提取字段。行程单不能继承配套发票的发票号码、不含税金额、税率或税额。

## ZIP

ZIP 始终只读。扫描 PDF member 并解析其自身字段；非 PDF member 仅在内部 plan 标记为忽略，不进入 output。ZIP 文件名不能提供发票号码或金额，原 ZIP 永久保留。
